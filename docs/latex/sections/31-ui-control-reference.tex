\section{Every control on screen, by its exact name}
\hypertarget{ui-reference}{}

This chapter lists each visible button, selector, and panel using the words
printed on screen. Bold text is always an exact UI label. Use it as a map when
a label is unfamiliar; hovering over most controls in the app also shows a
one-line tooltip.

\subsection{Navigation menu}
\hypertarget{ui-navigation}{}

The three-line button in the top corner (\emph{Open site navigation}) opens
the menu. Every page listed here is part of the same browser session: nothing
is sent to a server for simulation.

\UiTable{

examples, and protocol compiler.\\

QPU Documentation & Opens these PDF guides inside the app.\\

\subsection{Documentation in the Interactive workbench}
\hypertarget{ui-workbench-docs}{}

The workbench explains whatever you are examining, on the wires it uses. The
card is compact until you ask for more.

\UiTable{
Selected gate & The gate in the \textbf{Gate} selector, drawn on the wires
\textbf{Add gate to target} would use. Its table columns are labelled with
those wires (for example \textbf{A} on q0 and \textbf{t} on q2).\\
Step N of M on the canvas & Shown after \textbf{Step gate}, \textbf{Play
Sequence}, or \textbf{Run all}: the gate that just ran, on its own wires.\\
Back to selected gate & Returns the card to the selectors. Changing any
selector does the same.\\
On these wires now & The truth-table row that matches the wires' values
(the start states, or the values going into the step) and what it changes,
such as ``q2: 0 $\rightarrow$ 1. q0 and q1 unchanged.'' A wire in
superposition matches several rows at once.\\
Compiled protocol & A second card for the compiled process: its inputs,
outputs, and the row for the current start states.\\
Recursive frame & Shown while the step being examined is inside a recursive
call. Draws the frame being run with its heading (\texttt{DEPTH $d$ $\cdot$
LEVEL $\ell$ $\cdot$ TCO}), forward gates over a \texttt{forward
$\rightarrow$} rule, their inverses over a \texttt{$\leftarrow$ inverse}
rule, the frame's \textbf{IC} cycle line, and \texttt{RECUR $\downarrow$
D$(d-1)$} for the next frame. The current gate is highlighted.\\
Expand \ldots{} first frame & The same drawing, collapsed, whenever the
circuit has a recursive call but the playhead is outside it. Click to open
the first frame.\\
Learn more & Expands the full truth table (matching rows highlighted), how it
works, the target notes, syntax, child processes, the protocol source, and
the PDF link. Collapsed by default.\\
Try & On a row under Learn more: sets the start states to that row's inputs
and rewinds the circuit.\\
Child process entries & Expand in place to read the child's own notes; their
children expand the same way.\\
}

\paragraph{Long tables and lists.} Anything longer than 8 items is shown in
collapsible groups of at most 8, and groups are grouped again whenever there
would be more than 8 of them. So 1--8 rows show directly, 9--64 use one level
of groups, 65--512 two levels, and 513--4096 three. Groups of a complete
truth table are named by their shared leading inputs (for example
\code{A0 A1 = 01}). The Circuit correction lab's truth table uses the same
grouping and opens the groups that contain failing rows.

\subsection{Gate palette: ``Pick up a block''}
\hypertarget{ui-palette}{}

Click a block to select it, or drag it onto a wire of the circuit canvas. The
label printed on each block is shorter than the protocol instruction name:

\begin{center}
\begin{tabular}{llll}
\toprule
Block & Instruction & Block & Instruction\\
\midrule
X, Y, Z, H, S, T & same name & CX & \code{CNOT}\\
P & \code{PHASE} & CCX & \code{CCNOT} (Toffoli)\\
CZ, CY & same name & SW & \code{SWAP}\\
M & \code{MEASURE} & $\neg$ & \code{NOT}\\
AND, NAND, OR, XOR & same name & & \\
\bottomrule
\end{tabular}
\end{center}

\textbf{Preconfigured} holds the built-in gates. \textbf{Custom gates} holds
gates you registered from a process; it is empty until you register one.

\textbf{Inverse} toggles how the next drop is drawn and run. Off places the
forward gate. On places its dagger: the canvas prints $\dagger$ on the block.
S, T, and PHASE then use the negated angle. X, Y, Z, H, CNOT, CCNOT, CZ, CY,
and SWAP are their own inverses, so the dagger does not change the matrix.
MEASURE and the derived gates do not take the toggle. The same spelling in
source is \code{dg} or \code{inv}, as in \code{Hdg} or \code{invH}.

\textbf{Wrappers} holds three tools that tag a gate already on the canvas
instead of placing a new one:
\UiTable{
REC & Recursive wrapper. Pick it, then click a gate: the wrapper dialog opens
with \textbf{Recursive wrapper} ticked so you can set its depth.\\
IF & Pick it, then click a gate: the dialog opens with \textbf{IF / ELSE
wrapper} ticked, \textbf{Kind} set to IF, and \textbf{Equals} set to 1.\\
ELSE & The same, with \textbf{Kind} set to ELSE and \textbf{Equals} set
to 0.\\
}
While a wrapper tool is selected the tip under the canvas says so. Clicking the
same wrapper again cancels it. Picking an ordinary gate block also cancels it.

\subsection{Wrapper dialog: ``Gate wrappers''}
\hypertarget{ui-wrapper-dialog}{}

The dialog opens from a wrapper tool, or by clicking any gate that already
carries a wrapper. Its heading names the gate and its target wire.
\UiTable{
Recursive wrapper & Tags the gate as a recursive call.\\
Depth & The DEPTH shown in the teal badge above the gate (at least 1).\\
IF / ELSE wrapper & Makes the gate conditional.\\
Kind & \textbf{IF} or \textbf{ELSE}. Choosing ELSE sets \textbf{Equals} to
0; choosing IF sets it to 1. Either can then be changed. This is a display
label only when \textbf{Joined} is ticked; the test itself comes from
Equals/Value there.\\
Joined (test a gate) & Off (default): condition on one measured bit, using
\textbf{Classical bit} and \textbf{Equals} below. On: condition on a gate
expression, using the fields in \emph{Joined fields} below instead.\\
Classical bit & \emph{Joined off.} Which measured wire the condition reads,
shown as \textbf{q$n$ $\rightarrow$ c}. That wire needs a MEASURE
(\textbf{M}) before this gate.\\
Equals & \emph{Joined off.} The value that makes the gate run: 1 or 0.\\
Save & Applies the ticked wrappers and rewinds the run.\\
Cancel & Closes the dialog without changes.\\
Delete wrappers & Removes both wrappers and keeps the gate.\\
}

\paragraph{Joined fields (shown when Joined is ticked).}
\UiTable{
Gate & Which gate to test: any built-in or registered custom gate with one
result wire (the same rule as writing \code{IF (GATE ...) = V} --- see
\hyperlink{if-gate-expression}{Gate-expression conditions}). MEASURE, RESET,
and SWAP are not offered.\\
Input 1, Input 2, \ldots & One selector per \code{-I} wire the chosen gate
takes; the count updates when you change \textbf{Gate}.\\
Output & The \code{-O} wire the result is read from.\\
Inverse (dg/inv) & Shown only for a reversible gate. Tests the gate's dagger.\\
Phase angle & Shown only for PHASE, RX, RY, RZ, and CPHASE. $\theta$ in
degrees, as in the workbench.\\
Test & \textbf{equals} or \textbf{not equal to} (\code{=} / \code{!=}).\\
Value & \code{1p}, \code{0p}, or \code{sp}.\\
}
A line under these fields previews the exact test, for example
\texttt{Test: AND(q0,q1) = 1p}, using the same wording the canvas label and
the compiled protocol text use. Reopening a gate that already carries a
gate-expression condition --- written in the protocol text or built here ---
shows these fields filled in and ready to edit; Delete wrappers removes it.

\begin{cautionbox}[What each wrapper changes]
The \textbf{IF / ELSE} wrapper changes the run: the gate is skipped when the
condition does not match. With \textbf{Joined} off it is written to the
protocol editor as a \code{-IF} condition, such as
\code{Z -I $Q2:0 -O $Q2:0 -IF Q0=0}; with \textbf{Joined} on it is written as
an \code{IF (...) = V ... ENDIF} block around the gate. The
\textbf{REC} wrapper only labels the gate with a depth badge. The gate still
runs once, and the tag is not written to the protocol text. To repeat gates
DEPTH times, write a child process with \code{REC} or \code{TREC} and call
it with \code{RUNCHILD} \ldots{} \code{-DEPTH} $n$; see bounded recursion in
the Language Reference.
\end{cautionbox}

\subsection{Circuit canvas: ``Standard circuit diagram''}
\hypertarget{ui-canvas}{}

Each qubit row is one wire, labelled \textbf{q0}, \textbf{q1}, \ldots{} with
its start state. Time runs left to right: every gate occupies its own column.
When the circuit measures, one classical lane \textbf{c} sits underneath.
It is a clock for those readings, not a wire the particle moves onto. A slash
and a number give its width, which is the number of qubit wires. A circuit
with no measurement has no \textbf{c} lane.
\begin{itemize}
  \item \textbf{Placing a gate:} drop a block on a qubit row, or select a
  block and click the row. The row you drop on becomes the \emph{target}.
  Controls are chosen automatically from the lowest other qubit rows; use the
  workbench to choose them yourself. The \textbf{c} lane cannot be targeted.
  \item \textbf{Removing a gate:} click the gate symbol. Clicking the meter
  removes that measurement step. Later gates on the same qubit stay. A gate
  that carries a REC or IF/ELSE wrapper opens the wrapper dialog instead;
  use \textbf{Delete wrappers} there first.
  \item \textbf{Wire labels:} after compiling a protocol, each wire also
  shows its parameter name (for example \textbf{A} under \textbf{q0}).
  \item \textbf{Line styles:} every qubit wire is a single line.
  \textbf{c} is the classical lane. A black double stroke, not an arrow,
  drops from the meter to \textbf{c} at that column. The number beside the
  stroke is the bit whose reading happened at that time.
  \item \textbf{IF / ELSE:} a conditioned gate stays on its own wire. A yellow
  double line joins it to \textbf{c}, and a label under \textbf{c} names the
  branch and its test (\textbf{IF} \texttt{A=1}, \textbf{ELSE}
  \texttt{A=0}). After the bit is measured the branch that runs shows
  \texttt{$\checkmark$ taken}; the other shows \texttt{$\oslash$ skipped}
  and fades with dashed lines. Skipped gates are never removed. A
  gate-expression IF, such as \code{IF (AND -I A B -O B) = 1p}, has no bit
  on \textbf{c}: its yellow line spans the wires it reads, with a yellow tap
  on each, and its label shows the expression (\texttt{AND(A,B)} above
  \texttt{= 1p}) using the 0p/1p/sp state vocabulary, not bare 0/1/S. The
  wrapper dialog's \textbf{Joined} fields edit the same test, whether it came
  from the protocol text or was built there; see \emph{Wrapper dialog}.
  \item \textbf{Recursive call:} drawn once, not once per frame. A teal
  \textbf{D$n$} badge above it shows the current DEPTH and counts down as you
  step, then hides when the call is finished. A multi-gate recursive child is
  one \textbf{REC} box spanning its wires, captioned with the child name and
  depth range (for example \texttt{D5 $\rightarrow$ D1}).
  \item \textbf{Dashed markers:} a dashed vertical line across all wires is a
  whole-circuit marker, not a gate. \textbf{IC$n$} is an
  \code{INCREASECYCLE} boundary into cycle $n$. \textbf{S} and \textbf{L}
  are \code{SAVE_STATE} and \code{LOAD_STATE}, with the checkpoint name above
  the letter. The active marker turns red.
  \item \textbf{Outlines:} the step that just ran is red on a forward gate.
  An inverse gate is blue. The active inverse step is purple, including its
  connecting line. A collapsed REC box is red while a forward gate of the
  frame runs and purple while an inverse one runs.
  \item \textbf{Dagger:} an inverse gate prints $\dagger$ on its symbol
  (\code{H} becomes H$\dagger$). The forward gate keeps the plain symbol.
\end{itemize}

\subsection{Interactive workbench: ``Add particles, gates, and measurements''}
\hypertarget{ui-workbench}{}

The workbench places a gate with exactly the wires you choose.

\UiTable{
Gate & Which gate \textbf{Add gate to target} will place. Same list as the
palette.\\
Target particle & The wire the gate \emph{changes}. For a measurement, the
wire \textbf{Measure target} reads.\\
Control A & The first wire the gate \emph{reads}. Used by CNOT, CZ, CY, and as
the first input of CCNOT, AND, NAND, OR, and XOR.\\
Control B & The second wire the gate reads. Used by two-input gates (CCNOT,
AND, NAND, OR, XOR) and custom gates with two or more inputs. SWAP also uses
it as the wire to exchange with the target.\\
Phase angle & Appears for PHASE, RX, RY, RZ, and CPHASE. Sets $\theta$ in degrees.\\
Add gate to target & Appends the selected gate as the next column.\\
Add cycle boundary & Inserts an \code{INCREASECYCLE} marker. Advances the
logical stage; does not loop or repeat earlier gates.\\
Add particle / Remove particle & Adds or removes the last wire (up to six on
the canvas). After a compiled protocol, adds or removes a \code{PARAMS}
input instead; compile again afterwards.\\
Measure target & Measures only the selected target wire now, without adding
a meter to the circuit.\\
\emph{name} start & One selector per input wire: \code{0p} ($\ket0$),
\code{1p} ($\ket1$), or \code{sp} ($\ket+$). Changing it resets the run.\\
}

Gates that do not use a selector ignore it. Single-qubit gates use only
\textbf{Target particle}. A control can never equal the target, so the app
disables that choice and picks a free wire if needed.

\begin{center}
\WorkbenchControlMap{CCNOT}
\end{center}
\begin{beginnerbox}[Reading the picture]
The selectors on the left produce the diagram on the right. \textbf{Control A}
and \textbf{Control B} become the two filled dots: they are read and never
changed. \textbf{Target particle} becomes the $\oplus$: it is the only wire
that can change, and it changes by $t' = t\oplus(A\land B)$. The same mapping
applies to AND. For NAND, OR, and XOR only the rule written on the target
changes.
\end{beginnerbox}

\subsection{Run controls}
\hypertarget{ui-run-controls}{}

\UiTable{

Run all & Jumps straight to the final state. Useful once you trust the
circuit.\\
Step gate & Runs exactly one more gate. Disabled at the end of the

Reset state & Rewinds the run to the start states and clears measurements.

Speed & Playback speed for \textbf{Play Sequence}.\\
}

\subsection{QPU protocol compiler: ``Compile text into a circuit''}
\hypertarget{ui-compiler}{}

\UiTable{
SingleBitFullAdder, TwoBitFullAdder, FourBitFullAdder, PhaseDemo & Load and
compile a bundled protocol in one click.\\
Protocol editor & The text box. Editing it does not change the canvas until
you compile.\\
Compile protocol & Turns the editor text into canvas gates and resets the run.
The sentence beside the buttons summarizes the result or the error.\\
Download as .qpucir / Download as -qpucir.txt & Saves the editor text. The

Protocol checks & Live error and warning list for the editor text, with line

Open Correction Lab for guided help & Appears when checks find a problem.\\

}

\begin{cautionbox}[Canvas edits rewrite the editor]
Placing, removing, or clearing gates on the canvas regenerates the protocol
editor text from the canvas. Download a hand-written protocol before editing
its compiled circuit visually.
\end{cautionbox}
